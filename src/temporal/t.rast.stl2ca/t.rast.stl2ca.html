DESCRIPTION

t.rast.stl2ca extracts, for every category of a classification, the time series of a space-time raster dataset (STRDS), as the mean, median or other statistic of the pixels in that category. It then carries out a STL decomposition (Seasonal-Trend decomposition using LOESS) on each category's series and draws every category together on one multi-panel plot comparing the observed series, trend, seasonal and residual (remainder) components. Optionally, a robust Theil-Sen trend regression can be fitted to each category's deseasonalized series and drawn on the trend panel.

The categories come from either a CELL raster's own cell values (raster), or a vector map's features grouped by an attribute column (map/layer/column). This can, for example, be a land-cover raster, or a vector of administrative units grouped by region name. t.rast.stl2ca complements t.rast.stl, which can instead compare two datasets sampled at one, manually chosen area; use t.rast.stl for that case.

The module supports strds with absolute (calendar-dated) or relative (integer-stepped) time. Every category's series is regularized onto the same evenly spaced time axis, and then run through statsmodels.tsa.seasonal.STL.

About STL

Environmental time series derived from remote sensing, like a vegetation index, land surface temperature, snow cover, or soil moisture, are normally composed of:
  • A repeating seasonal pattern, e.g. vegetation greening up every spring and senescing every autumn;
  • A slower trend, e.g. a multi-year changes such as recovery after a disturbance, or climate change;
  • Short-term residual variation that is left over once season and trend are removed. These include normal day-to-day variation, sensor noise, residual cloud contamination, or one-off events such as a fire or a flood.

STL is a procedure that separates these three temporal patterns. It models the observed value at each date as observed = trend + seasonal + residual.

It estimates the trend and seasonal patterns by repeatedly fitting LOESS (LOcally Estimated Scatterplot Smoothing) curves. These are flexible local regressions that do not assume a fixed global functional shape. STL is robust, handles long seasonal cycles, and (in its robust variant) can down-weight outliers such as undetected clouds.

The module can be run with default settings to explore patterns. The minimum input is the strds and either raster or map. If the maps in the strds are not regularly spaced, you will need to provide the required frequency as well. For more information about this parameter and other fine-tune options, see the next section.

The categories

Each category is sampled as the mean, median or other statistic of the pixels that belong to it, in exactly one of two ways:
  • raster: a CELL (integer) raster whose distinct cell values are the category codes. There is no per-category breakdown beyond the raster's own values. You need to reclassify it first with r.reclass if you need a coarser grouping.
  • map (with layer and column): a vector map, rasterized and grouped by an attribute column. Every feature becomes its own category by default (column=cat, i.e. not set); giving a different column groups features that share the same value of that column into one category instead, labelled with that value. column can be numeric or text.

raster and map are mutually exclusive; exactly one is required.

By default every distinct category found is processed. categories restricts this to a chosen subset, given as a comma separated list of either the category's raw value (raster) or its label (the column value, or the raster's own category label if it has one). For example categories=1,3 or categories=forest,water.

Either way, the module samples at the current computational region's resolution. Set the region with g.region before running if needed. A category with no overlap with the current region, or no non-null data at any registered timestep, is skipped with a warning rather than aborting the whole run.

The per-timestep pixel values within a category are summarized by statistic: mean (the default), median, min, max or percentile. percentile requires percentile_value (0-100). This statistic applies to every category alike, so they stay comparable; it cannot be set independently per category. Note that median and percentile require t.rast.univar's extended-statistics mode, which can require a lot of memory if used with large rasters.

The -d flag additionally shades a band around each category's Observed series showing the spread of pixel values at each timestep: ±1 standard deviation for mean, or the interquartile range (25th-75th percentile) for median. It is only valid with statistic=mean or statistic=median. Gaps in the band (missing timesteps) are always filled by linear interpolation, regardless of the interpolation option, so a curvature-fitting method chosen for the series itself cannot overshoot and bulge the band past its true local range.

A standard deviation or interquartile range estimated from very few pixels is unreliable and can spike far past the genuine spread, typically on a near-total-cloud timestep where only a handful of pixels survive. min_pixels guards against this. At timesteps with fewer non-null pixels than this, the band is left out there too and filled the same way as any other gap.

Drawing

Every category gets its own color, from colormap (a Matplotlib colormap name, default tab10), with one legend for the whole figure, placed below the bottom panel so it never sits on top of a line. Once there are more categories than the chosen colormap has distinct colors, a continuous colormap (viridis) is used instead, sampled evenly across its range (a warning names this when it happens). The dispersion band (-d), seasonal envelope (seasonal_envelope) and Theil-Sen trend line (-s) are each drawn in the category's own color.

Interactive plot

The -i flag writes an interactive HTML plot (using Plotly, a separate Python package from Matplotlib) instead of a static image, with the same panels, colours and legend as the static figure. output must then end in .html; if output is left out, the plot is opened in a browser tab instead of being shown in a window. What it adds over the static figure:
  • Click a category's legend entry to highlight it. This will cause the other category's lines, across every panel, to fade to a thin grey. You can continue to click other entries to highlight several at once. Clicking a highlighted entry again removes it from the highlight.
  • Dragging across any panel zooms into that time range. Double-click to reset the zoom.
  • Hovering any panel shows the date and category's value at that point, and draws a crosshair through every panel at that date.
  • A "Trend statistics" tab in the top-left corner opens a sidebar holding the same table stats_output writes to a file (see below), whether or not stats_output is actually given.

plots, -d, -s, seasonal_envelope, vlines, colormap, title, line_width and fontsize all carry over unchanged. backend, dpi, plot_dimensions and style are Matplotlib-only and are ignored for the HTML plot with a warning.

Absolute vs. relative time

The tool handles both temporal types of strds. For absolute-time datasets the x-axis of the plot is labelled with dates. For relative-time datasets the x-axis is labelled "Time step".

Regularization

STL requires an evenly spaced, gap-free series. Each category's series is therefore resampled onto a regular axis and any gaps are then filled in. Three options control this:

frequency sets the spacing of the regular axis for absolute-time datasets. It is a pandas offset alias. Common choices are D (daily), W (weekly), MS (month start), or e.g., 16D for a 16-day composite series. For absolute-time datasets that are already regularly spaced, frequency may be omitted and the spacing is inferred. For irregular data you should set it explicitly to fit the desired / intended spacing.

step sets the spacing for relative-time datasets, as an integer in the dataset's own time unit (frequency is ignored for relative-time datasets). If step is omitted, the dataset granularity reported by t.info is used, and the extent of the regular axis is taken from the data. Observations that do not fall on a grid node are snapped to the nearest node (with a warning), and two observations landing on the same node are averaged.

interpolation chooses how gaps left after resampling are filled. The default is a linear interpolation. If gaps are uneven, you might want to use the time option, which takes into account the actual time distance between observations. For the other options, nearest, pchip, akima, cubic, quadratic, spline and polynomial, see the manual page of the Pandas Series.interpolate function, which this module uses for the gap filling.

You will normally want to make sure the frequency (or step) matches the real sampling of your data. If these are not matching, your data will be resampled. For example, setting data that is actually 16-day composites to D (daily) will create many interpolated points and smoothen the data series.

Decomposition (STL)

The decomposition wraps statsmodels.tsa.seasonal.STL, run with the same settings on every category. Its most important parameter is period, which is tied to the regularized frequency (or, for relative-time data, the step / granularity). It is the number of observations in one full seasonal cycle. For example 12 for monthly data, 23 for a 16-day composite series (≈ 365 / 16), or 365 for daily data with an annual cycle. If period is not given it is estimated from the resampled frequency (or, for relative-time data, the dataset granularity). Set it explicitly whenever you are unsure the inference will be right, or when your cycle is not annual.

The remaining STL options fine-tune the LOESS smoothers. For users familiar with R's stl() function, many of these parameters are similar or identical, although the defaults may differ.

seasonal: length of the seasonal smoother (odd integer ≥ 7). Smaller values let the seasonal shape change quickly from cycle to cycle; larger values force a more stable, near-constant season. The equivalent parameter in R's stl() function is s.window.

trend: length of the trend smoother (odd integer). Larger values give a smoother, stiffer trend that ignores short wiggles; smaller values let the trend bend more. If left empty, statsmodels derives a default from the period and seasonal window. The equivalent parameter in R's stl() function is t.window.

low_pass: length of the low-pass smoother (odd integer ≥ 3). This is an internal step separating season from trend; the default (the smallest odd number larger than period) is almost always fine. The equivalent parameter in R's stl() function is l.window.

seasonal_degree, trend_degree, low_pass_degree: the degree of the local polynomial each LOESS uses (0 = locally constant, 1 = locally linear). statsmodels defaults to 1. R's stl() also uses 1 for the trend (t.degree) and low-pass (l.degree) smoothers, but 0 for the seasonal smoother (s.degree).

seasonal_jump, trend_jump, low_pass_jump: control the trade-off between speed and accuracy. The LOESS is evaluated every jump observations and interpolated in between; 1 (the default) evaluates at every point and is the most exact.

-r (robust flag): turns on robust fitting, which iteratively down-weights outliers. This is worth enabling when residual cloud or sensor spikes are distorting the fit.

Seasonal amplitude envelope

The seasonal_envelope option draws a rolling envelope of the seasonal component on the Seasonal panel, for every category: a moving window one seasonal period wide, centered on each point, tracks the local extremes of the seasonal cycle. It can be used to show a decrease or increase in the amplitude over time (for example, a vegetation index whose greening/senescence amplitude strengthens or dampens across years), and to compare that change between categories.

The value is the fraction trimmed off each end of the window before taking the envelope: seasonal_envelope=0 uses the plain min/max of the window, while e.g. seasonal_envelope=0.1 uses its 10th/90th percentile instead, so that one unusually extreme cycle doesn't dominate the envelope. A window that doesn't fully fit (the first/last half-period of the series) is left as a gap rather than computed from a partial window.

Trend line and statistics

Beyond the visual decomposition, the tool quantifies the long-term change in each category by fitting a robust Theil-Sen regression (SciPy's theilslopes) to its deseasonalized observed series (trend + residual, equivalently observed - seasonal), reported with its slope and a monotonic-trend p-value from Kendall's rank-correlation test (SciPy's kendalltau; note that this differs from a full Mann-Kendall test, which applies tie and variance corrections, so the reported p-values may differ slightly when the data contain ties).

The -s flag draws the Theil-Sen line on the trend panel; stats_output writes its numbers (slope, Kendall's tau, p-value) to a CSV file, one row per category, regardless of -s -- see "Output" below.

The slopes are expressed per observation of the regularized series, i.e., per step of the chosen frequency (absolute series) or step (relative series). For a daily (D) series this is per day; for a 16-day composite (16D) it is per 16-day step, for a monthly (MS) series per month, and so on. Use slope_unit to express them per a different, readable calendar unit instead (day/week/month/year), or auto (the default) to pick one from the series span.

A note on significance. The reported p-value (the Kendall test behind Theil-Sen) assumes independent residuals. Deseasonalized environmental series are almost always serially autocorrelated, which inflates significance (p-values come out too small). The values here therefore do not account for serial autocorrelation. So, for a formal inference, you should consider a trend-free pre-whitening of the series, or a variance correction such as the Hamed–Rao modification of the Mann-Kendall test.

The STL trend LOESS has to extrapolate at both ends of the series because, near the boundaries, it can only use data from one side. The corresponding ends of the deseasonalized series are therefore the least reliable and can disproportionately influence the fitted regression. The trend_trim option reduces this edge effect by dropping a portion of each end before fitting. The trimming amount is specified as a fraction of the effective trend window:

  • none (default) uses the whole series;
  • 0.1 / 0.25 remove only the outermost, most biased points;
  • 0.5 removes the entire theoretically-extrapolated zone (about half the trend window at each end);
  • 1 is the most conservative.

If you see a fitted line being pulled by an upswing or downswing right at the edge of the plot, increasing trend_trim is the appropriate fix.

Trend breakpoints

A single Theil-Sen slope over the whole series averages away a real turning point, for example a rise, a decline, and a renewed rise. The breakpoints option splits the fit of each category into separate segments instead: one or more dates (absolute-time) or time steps (relative-time), each starting a new segment, with the series' own start and end as the outer boundaries. Each segment gets its own row in stats_output, labelled by its date (or step) range, and (with -s) its own Theil-Sen line on the plot. trend_trim still only trims the series' true start and end; an interior breakpoint is not a LOESS edge, so no trim is applied there. Combine breakpoints with matching vlines values to also mark them on the plot. A segment left with too few observations after trimming (fewer than 4) is rejected with an error naming it, rather than silently reporting a near-meaningless fit.

Vertical reference lines

The vlines option draws one or more dashed vertical reference lines across every panel, for example to mark a known event (a fire, flood, land-use change, or similar) against the decomposition. Give one or more dates (vlines=2019-08-15) for absolute-time strds, or one or more integer time steps for relative-time strds; separate multiple values with commas (vlines=2015-01-01,2019-08-15). Optional text labels for each line can be given with vlines_labels, in the same order and count as vlines (vlines_labels=Fire,Flood); they are shown rotated above the top panel.

Output

By default the multi-panel plot is shown in an interactive window. If output is given, the plot is instead saved to that file and the image format is taken from the file extension (.png, .pdf, .svg, ...). See "Interactive plot" above for the -i flag, which writes an HTML plot instead and changes output's meaning. The rest of this section is about the static image. Plot appearance is controlled by dpi (resolution, default 300) and plot_dimensions (width,height in inches). The style option applies a Matplotlib style sheet to the plot, e.g. style=ggplot. It also accepts the path to a custom .mplstyle file, e.g. to set a thinner axes.linewidth than any built-in style does.

The plots option selects which of the four panels (observed, trend, seasonal, residual) are drawn. By default all four are shown; list a subset to leave the others out, for example plots=observed,trend to draw only the observed series and its trend. At least one panel is required. The Theil-Sen trend line (-s) is only drawn when the trend panel is included. When plot_dimensions is not set, the default figure height scales with the number of selected panels (about 2 inches each, so the full four-panel figure is 8x8 inches).

The backend option selects the matplotlib rendering backend. You rarely need it: Agg is chosen automatically when writing to a file, and WXAgg (an interactive window) when no output file is given. Override it only if your system needs a different interactive backend (e.g. TkAgg, Qt5Agg).

stats_output, when given, writes the Theil-Sen/Kendall trend statistics (slope, tau, p-value, the reporting unit, number of observations fitted) to a CSV file, one row per category -- and one row per breakpoints segment, when given, in addition to the whole-series row. This is independent of -s: the statistics are computed either way, this option just decides whether they are written out. With -i, the same table is also always shown in the HTML output, in a sidebar opened from the "Trend statistics" tab -- see "Interactive plot" above -- whether or not stats_output is given.

Subsetting and performance

The where option accepts a temporal WHERE clause (as used by other t.* modules) to restrict the analysis to a subset of timestamps, for example a particular range of years. Note that in the interactive plot, you can plot the whole range and select the range you are interested in in the plot (see above).

The nprocs option sets the number of parallel processes t.rast.univar uses for the zonal extraction, which covers every category in one call; this can make the module substantially faster to run, but setting it higher than the number of CPU cores available just adds contention rather than speed. The main per-run cost is t.rast.univar itself, which runs once per registered map in strds (filtered by where, if given): a strds with very many registered maps can take a while regardless of region size or category count, since the dominant cost is then the number of maps, not the number of pixels. The module automatically shrinks the region it samples at to the categories' own extent first (see "The categories" above), which helps substantially when the categories occupy only a small part of a much larger current region, but does not reduce the per-map cost of a strds with many registered maps.

NOTES

This addon requires the Python packages numpy, pandas, scipy, matplotlib and statsmodels. They are all pip-installable, e.g. 
pip install numpy pandas scipy matplotlib statsmodels

If a dependency is missing the module exits with a message indicating which package to install. The -i (interactive HTML plot) flag additionally needs plotly (pip install plotly), checked only when -i is actually used -- an ordinary run never needs it installed.

  • pandas builds the time-indexed series, resamples it onto the regular axis (Series.resample) and fills gaps (Series.interpolate).
  • statsmodels performs the STL decomposition (statsmodels.tsa.seasonal.STL), splitting each series into trend, seasonal and residual components.
  • scipy fits the robust Theil-Sen trend line (scipy.stats.theilslopes) and the monotonic-trend p-value from Kendall's rank correlation (scipy.stats.kendalltau).
  • numpy provides the array operations underlying the above, and matplotlib renders the multi-panel plot.

Not every option of t.rast.stl is available here: there is no second strds (strds2), no OLS trend line on the plot (-o), no monotone GAM trend curve (-g/-b/gam_direction), no point-vector output (vector), and no transient temporal-outlier filter (temporal_outliers) -- all of these would need to be meaningful across an arbitrary number of categories rather than one or two fixed areas; some may return in a future version.
